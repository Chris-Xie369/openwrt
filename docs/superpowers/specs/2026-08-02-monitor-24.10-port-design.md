# monitor 24.10 移植设计（uClibc → musl）

## Context

HLK-7688A gateway 的 crontab 第一条 `*/2 * * * * monitor` 需要 monitor C 程序（常驻进程 + flock 单例锁 + MQTT 心跳看门狗），但当前 monitor 二进制是 14.10 uClibc 编译，24.10 musl 上无法运行（`/lib/ld-uClibc.so.0` 不存在）。本设计将 monitor 移植到 24.10，完全复用 gateway app 已验证的移植模式。

## 范围

- monitor 核心模块编译（Makefile OBJS 中的模块：iota/MQTT + periph GPIO/ADC/serial + file/json + main + sm4）
- 不含 video/lora/dtu/ftp/http/log 模块（不在 OBJS，不编译）
- 不含 monitor 功能改动（纯移植，行为不变）

## 技术评估（探索结论）

| 障碍 | 评估 | 解法 |
|------|------|------|
| 工具链 14.10 uClibc → 24.10 musl | 低 | OpenWrt 包 Makefile Build/Compile 命令行覆盖（gateway 模式） |
| pwrapper（libpwrapper.a，无源码） | 极低 | 仅 3 处 pthreadSpawn 调用（main.cpp:141/163/179），全传 NULL 参数；自写 ~20 行 pwrapper.c |
| polarssl | 无 | Makefile LIBS 残留，代码无实际 API 调用，去掉 |
| 库依赖 | 低 | paho-mqtt3as/ssl/crypto/z/curl/rt/m/pthread，24.10 staging_dir 全有，不需 ffmpeg |
| uClibc 特定 API | 无 | 无 backtrace/syslog 等；cJSON 用标准 C |
| video/lora/dtu 模块 | 无 | 不在 OBJS，不编译，无依赖 |

## 约束

- monitor 源码改动在 worktree `/home/otn/bump-detect/worktree/openwrt-24.10-port`（分支 `openwrt-24.10-port`），不改主仓库 main
- 现有 C/C++ 源码零改（pwrapper.c 是新文件，Makefile 仅加 OBJS + 规则）
- commit message 末尾加 `Co-Authored-By: Claude Fable 5 <noreply@anthropic.com>`
- monitor 是常驻进程（flock LOCK_EX|LOCK_NB 单例锁），crontab 每 2 分钟作为看门狗尝试重启（已在跑则锁失败退出）

## 设计

### 域 1：gateway worktree（openwrt-24.10-port 分支）

#### ① 新建 `monitor/ssde/pwrapper.c`

替代 libpwrapper.a（同目录），实现 monitor 唯一用到的 pwrapper 函数：

```c
#include <pthread.h>
#include <stddef.h>

/* monitor 唯一调用的 pwrapper 函数：变参线程创建。
 * 3 处调用（main.cpp:141/163/179）全传 NULL 参数（无线程 arg），
 * 简化为 pthread_create(funcptr, NULL)。priority 忽略（无实时调度需求）。 */
int pthreadSpawn(pthread_t *ptid, int priority, size_t stacksize,
                 void *funcptr, unsigned args, ...)
{
    pthread_attr_t attr;
    pthread_attr_init(&attr);
    if (stacksize)
        pthread_attr_setstacksize(&attr, stacksize);
    int ret = pthread_create(ptid, &attr, (void *(*)(void *))funcptr, NULL);
    pthread_attr_destroy(&attr);
    return ret;
}
```

#### ② 改 `monitor/Makefile`（3 处微调）

**a) OBJS 末尾加 pwrapper.o**：
```makefile
OBJS = sh_process.o poll_process.o ... sm4.o pwrapper.o
```

**b) 加编译规则**（在 sm4.o 规则后）：
```makefile
pwrapper.o: ssde/pwrapper.c
	$(CC) $(CFLAGS) -c ssde/pwrapper.c -o pwrapper.o $(HEADER_PATH)
```

**c) LIBS 去掉死依赖**：
```makefile
# 旧：
LIBS = $(LIB_PATH) -lpaho-mqtt3as -lssl -lcrypto -lpolarssl -lz -lpwrapper -lrt -lm -lcurl
# 新（去 polarssl=无调用，pwrapper=自实现）：
LIBS = $(LIB_PATH) -lpaho-mqtt3as -lssl -lcrypto -lz -lrt -lm -lcurl
```

> LIBS 实际被 OpenWrt 包 Makefile 命令行覆盖（见域 2③），此处清理仅为可读性。

### 域 2：固件仓库（openwrt-24.10）

#### ③ 新建 `package/utils/monitor/Makefile`

复用 gateway 包模板（`package/utils/gateway/Makefile`），适配 monitor 的 Makefile 结构：

```makefile
include $(TOPDIR)/rules.mk

PKG_NAME:=monitor
PKG_VERSION:=1.0
PKG_RELEASE:=1

USE_SOURCE_DIR:=/home/otn/bump-detect/worktree/openwrt-24.10-port/monitor

include $(INCLUDE_DIR)/package.mk

define Package/monitor
  SECTION:=utils
  CATEGORY:=Utilities
  TITLE:=Gateway monitor daemon (MQTT heartbeat + watchdog)
  DEPENDS:=+libpaho-mqtt-c +libopenssl +zlib +libcurl +libpthread
  PKGARCH:=mipsel_24kc
endef

define Package/monitor/description
 C monitor daemon for HLK-7688A gateway: MQTT heartbeat uplink, flock
 singleton, crontab watchdog every 2 min. Cross-compiled from external
 source via USE_SOURCE_DIR.
endef

# monitor internal include paths
MONITOR_INC := \
	-I./inc/base -I./inc/util -I./inc/third_party/zlib/ \
	-I./inc/third_party/cjson/ -I./inc/third_party/posix/ \
	-I./inc/http -I./inc/iota/base -I./inc/iota/agentlite \
	-I./inc/iota/service -I./inc/iota/protocol -I./inc/iota/conn \
	-I./inc/periph -I./inc/common -I./inc/file \
	-I./inc/third_party/sm4/ -I./inc/monitor -I./inc

MONITOR_LIBS := \
	-L$(STAGING_DIR)/usr/lib \
	-lpaho-mqtt3as -lssl -lcrypto -lz -lrt -lm -lcurl -lpthread

define Build/Compile
	$(MAKE) -C $(PKG_BUILD_DIR) clean || true
	$(MAKE) -C $(PKG_BUILD_DIR) all \
		CC="$(TARGET_CC)" \
		CXX="$(TARGET_CXX)" \
		CFLAGS="$(TARGET_CFLAGS) -std=c99 -fPIC -fsigned-char -ffunction-sections -fdata-sections -w" \
		CXXFLAGS="$(TARGET_CXXFLAGS) -std=c++11 -fPIC -fexceptions -fsigned-char -ffunction-sections -fdata-sections -w" \
		HEADER_PATH="-I$(STAGING_DIR)/usr/include $(MONITOR_INC)" \
		LIB_PATH="-L$(STAGING_DIR)/usr/lib" \
		LIBS="$(MONITOR_LIBS)"
endef

define Package/monitor/install
	$(INSTALL_DIR) $(1)/usr/bin
	$(INSTALL_BIN) $(PKG_BUILD_DIR)/monitor $(1)/usr/bin/monitor
endef

$(eval $(call BuildPackage,monitor))
```

> **LIBS 覆盖注意**：monitor 自己的 Makefile 链接行是 `$(CXX) ... $(OBJS) $(LIBS) -lpthread -luci -lubox`。命令行 LIBS 覆盖 `$(LIBS)` 变量，但 `-luci -lubox` 在链接命令里硬编码。monitor 的 OBJS 不含 uci_util.o，大概率不引用 uci/ubox 符号；若链接报 undefined，加 `-luci -lubox` 到 MONITOR_LIBS。

#### ④ `mt76x8.mk` DEVICE_PACKAGES 加 `monitor`

`make defconfig` 后验证 `CONFIG_PACKAGE_monitor=y`（若 not-set，手动 sed 翻 y 再 defconfig）。

## 验证

### 编译验证
1. `make package/monitor/compile V=s` → 无报错，pwrapper.o 链接通过
2. 若报 undefined reference：分析缺失符号，按需补 pwrapper.c 函数或加库到 MONITOR_LIBS

### 镜像验证
3. `make` → 镜像含 monitor（manifest 有 `monitor` 行）
4. sysupgrade 大小 < 32448k

### 设备验证
5. `/usr/bin/monitor` 存在且可执行
6. 手动 `monitor &` → 不崩溃，dmesg/app 日志无异常
7. `pgrep monitor` → 常驻运行
8. crontab 每 2 分钟触发 → flock 单例锁生效（第二个实例退出，不冲突）
9. MQTT 心跳上报正常（云端收到设备在线）

## 风险

| 风险 | 等级 | 缓解 |
|------|------|------|
| uClibc→musl 隐藏 API 差异 | 中 | gateway app 已验证 musl 兼容（同华为云 SDK），monitor 共享 iota/paho/curl 栈；编译报错逐一修 |
| pthreadSpawn 变参语义误判 | 低 | 3 处调用全传 NULL 参数（`MqttHeartTransMission` 无参函数），简化实现已覆盖；若链接报其他 pwrapper 函数 undefined 再补 |
| -luci -lubox 硬编码在链接行 | 低 | OBJS 无 uci_util.o，大概率不引用；报 undefined 则加库 |
| monitor 镜像体积（~750KB） | 低 | flash 32448k 充裕（当前固件 14M） |
| monitor 功能未在 24.10 验证过 | 中 | 分步验证：先编译通过 → 手动跑不崩 → MQTT 心跳 → crontab 守护 |
